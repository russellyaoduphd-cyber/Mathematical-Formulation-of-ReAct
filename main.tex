\section{Scope}

ReAct interleaves language-model reasoning with actions that interact with an external environment \cite{yao2023react}. The purpose of this note is to give that interaction a minimal mathematical representation. The goal is not to claim that the original ReAct paper is written in this formalism, and not to introduce a new training algorithm. Instead, we want a notation that makes the following objects explicit:
\begin{enumerate}[label=(\roman*)]
    \item what information is available to the agent,
    \item what is internal reasoning and what is an external action,
    \item how observations from the environment enter the next decision, and
    \item what objective would be optimized if the ReAct policy were to be learned.
\end{enumerate}

A useful principle throughout the note is to avoid assuming a compact Markov state before one has been identified. We therefore begin with the full interaction history.

\section{Interaction History}

Let \(q\) denote the task or query given to the agent. At interaction round \(t\), define
\begin{equation}
    h_t
    =
    \bigl(
    q,
    r_0,a_0,o_1,
    r_1,a_1,o_2,
    \ldots,
    r_{t-1},a_{t-1},o_t
    \bigr),
    \label{eq:history}
\end{equation}
where
\begin{itemize}
    \item \(r_k\) is the reasoning generated by the language model at round \(k\),
    \item \(a_k\) is the external action taken at round \(k\), and
    \item \(o_{k+1}\) is the observation returned by the environment after that action.
\end{itemize}

Thus, \(h_t\) contains all information available to the agent immediately before its reasoning at round \(t\). The initial history is simply
\[
h_0=(q).
\]

Using \(h_t\) rather than a state \(s_t\) is deliberate. In many ReAct settings, the current observation alone is not sufficient to determine what the agent should do next. Previous reasoning, tool calls, failed attempts, and returned observations may all matter. If a compact sufficient representation is later available, one may define
\[
s_t=\phi(h_t)
\]
and work with \(s_t\) instead.

\section{One ReAct Round}

A ReAct round contains three conceptually different operations: internal reasoning, external action, and environmental feedback.

\subsection{Reasoning}

Conditioned on the current history, the language model first generates a reasoning step
\begin{equation}
    r_t
    \sim
    \pi^{\mathrm{R}}_{\theta}(\cdot\mid h_t).
    \label{eq:reason}
\end{equation}

The important point is that \(r_t\) is an \emph{internal computational action}: it changes the context available to the model, but it does not by itself change the external environment.

\subsection{External action}

After reasoning, the agent generates an action
\begin{equation}
    a_t
    \sim
    \pi^{\mathrm{A}}_{\theta}(\cdot\mid h_t,r_t),
    \label{eq:action}
\end{equation}
where \(a_t\) may be a search query, a tool call, an API request, an action in a game, or any other operation exposed by the environment.

The notation \(\pi^{\mathrm{R}}_{\theta}\) and \(\pi^{\mathrm{A}}_{\theta}\) does not require two different models. In standard ReAct, both may be understood as two conditional uses of the same autoregressive language model.

\subsection{Observation and history update}

Let \(x_t\) denote the latent state of the external environment. A general environment model is
\begin{align}
    x_{t+1} &\sim P(\cdot\mid x_t,a_t), \\
    o_{t+1} &\sim O(\cdot\mid x_{t+1}),
\end{align}
where \(P\) is the environment transition kernel and \(O\) is the observation kernel. In a deterministic tool environment, these kernels may of course be deterministic.

The new observation is appended to the interaction history:
\begin{equation}
    h_{t+1}
    =
    h_t\oplus(r_t,a_t,o_{t+1}),
    \label{eq:update}
\end{equation}
where \(\oplus\) denotes concatenation.

Equations \eqref{eq:reason}--\eqref{eq:update} give the basic ReAct loop:
\[
\boxed{
h_t
\;\longrightarrow\;
r_t
\;\longrightarrow\;
a_t
\;\longrightarrow\;
o_{t+1}
\;\longrightarrow\;
h_{t+1}.
}
\]

\section{Termination and Task Reward}

The interaction terminates when the agent produces a designated finishing action, which we denote by
\[
a_T=\texttt{Finish}(\hat y),
\]
where \(\hat y\) is the final answer or solution.

Let \(R_{\mathrm{task}}\) denote the terminal task reward. For a task with a verifiable answer \(y^\star\), the simplest example is
\[
R_{\mathrm{task}}
=
\mathbf{1}\{\hat y=y^\star\}.
\]
More generally, \(R_{\mathrm{task}}\) may measure task success, solution quality, or any other externally specified criterion.

If the ReAct policy itself is to be optimized, the basic objective is
\begin{equation}
    J(\theta)
    =
    \mathbb{E}_{\pi_\theta,P,O}
    \left[
        R_{\mathrm{task}}
    \right].
    \label{eq:objective}
\end{equation}

This objective is only a mathematical description of what policy optimization would mean. ReAct itself can be used purely as a prompting framework with a fixed pretrained language model, in which case \(\theta\) is not updated.

\section{A Unified View: Internal and External Actions}

The previous section follows the familiar ReAct cycle of reasoning followed by an external action. For analysis, it is also useful to place both operations in one action space.

Let
\[
\mathcal{U}
=
\mathcal{U}_{\mathrm{int}}
\cup
\mathcal{U}_{\mathrm{ext}}
\cup
\{\texttt{Stop}\},
\]
where
\begin{itemize}
    \item \(\mathcal{U}_{\mathrm{int}}\) contains internal reasoning operations,
    \item \(\mathcal{U}_{\mathrm{ext}}\) contains actions that interact with the environment, and
    \item \(\texttt{Stop}\) terminates the process and returns an answer.
\end{itemize}

A history-dependent policy can then be written as
\begin{equation}
    u_k
    \sim
    \Pi_\theta(\cdot\mid H_k),
    \qquad
    u_k\in\mathcal{U},
    \label{eq:unifiedpolicy}
\end{equation}
where \(H_k\) is the complete context before operation \(k\).

The transition depends on the type of operation:
\begin{itemize}
    \item if \(u_k\in\mathcal{U}_{\mathrm{int}}\), the external world is unchanged and the generated reasoning is appended to the context;
    \item if \(u_k\in\mathcal{U}_{\mathrm{ext}}\), the environment is queried or changed and a new observation is appended to the context;
    \item if \(u_k=\texttt{Stop}\), the episode terminates.
\end{itemize}

This unified representation is useful because it identifies the central structural feature of ReAct: the policy alternates between computation that changes the agent's context and actions that obtain information from or change the external environment.

\section{Relation to an MDP or POMDP}

There are two levels of state in the formulation.

First, the external environment may have a latent state \(x_t\). The agent generally does not observe \(x_t\) directly, so the external problem can naturally be partially observed.

Second, the agent has access to the full interaction history \(h_t\). The policy is therefore written as
\[
\pi_\theta(\cdot\mid h_t)
\]
rather than assuming that the most recent observation is a sufficient state.

If one defines the augmented state to be the full history,
\[
s_t^{\mathrm{aug}}=h_t,
\]
then the induced interaction can be represented as a Markov process on this augmented state space. Equivalently, when a probabilistic model of the latent environment is available, one could replace the full history by a belief state
\[
b_t(x)
=
\mathbb{P}(x_t=x\mid h_t).
\]

For the present formulation, however, no particular compression of \(h_t\) is required.

\section{Optional Extension: Cost of Reasoning and Acting}

The task-reward objective in \eqref{eq:objective} treats additional reasoning and tool use as free. If efficiency matters, a natural extension is to assign costs to computation and interaction:
\begin{equation}
    J_{\lambda}(\theta)
    =
    \mathbb{E}
    \left[
        R_{\mathrm{task}}
        -
        \sum_{k=0}^{K}
        c(u_k)
    \right].
    \label{eq:costobjective}
\end{equation}

For example, \(c(u_k)\) may represent token usage, tool-call cost, latency, or some weighted combination of them. This extension turns the problem into a tradeoff between task performance and the resources used to obtain that performance.

Importantly, \eqref{eq:costobjective} is an extension of the basic ReAct formulation, not an assumption required by ReAct itself.

\section{What This Formulation Does and Does Not Claim}

The formulation can be summarized by four points:
\begin{enumerate}[label=(\arabic*)]
    \item ReAct is represented as a history-dependent sequential interaction between a language model and an external environment.
    \item Reasoning is treated as internal computation that changes the agent's context, while actions interact with the external environment and generate observations.
    \item The same language model may generate both reasoning and actions; the notation does not assume separate models.
    \item If one later wishes to optimize the agent, the natural object is the history-dependent policy governing this interaction.
\end{enumerate}

The note does \emph{not} assume a particular RL algorithm, a separate learned router, or a particular multi-agent architecture. Those are possible extensions only after the single-agent interaction has been defined clearly.

\paragraph{Question for discussion.}
Once ReAct is written as a sequential decision process, a natural next question is whether the allocation of computation and external interaction should itself be treated as a learnable decision problem. This question is intentionally left open here.
